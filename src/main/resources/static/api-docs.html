REST API reference

Every business operation the clinic performs is also available as a web service under /api/v1. The browser interface and these endpoints call the same service objects, so a booking made here is validated identically, takes its number from the same stored procedure, and is refused by the same unique index.

Checking the API…

Authentication

The API uses the same session cookie as the web interface. Sign in with a form POST to /login, keep the SESSIONID cookie, then call GET /api/v1/session to obtain your CSRF token. Send that token in the X-CSRF-Token header on every POST.

A dedicated API-key scheme would be more conventional for a public API. It was not built because it would be a second authentication path to secure and to test, and this API's clients are the clinic's own tools. Recorded as a deliberate decision rather than an omission.

Status codes

StatusMeaning
200OK
201Created, with a Location header
400The body is not valid JSON
401Not signed in
403Signed in, but the role or CSRF token is wrong
404No such resource — or it is not yours
409Conflict: slot taken, already billed, wrong status
422Well-formed, but a field failed validation
500Logged in full; the response carries no internal detail

Why 404 and not 403 for another patient's record

A 403 confirms that the resource exists. Appointment and bill numbers are sequential, so an attacker could count the clinic's bookings by observing which numbers answer differently. Returning 404 for both "no such number" and "not yours" leaks nothing. 403 is reserved for role-level refusals, where nothing is revealed. This is assumption A6 in the design decisions.

Worked example

# 1. Sign in and keep the cookie
curl -c jar.txt -X POST -d "username=admin&password=Admin@123" \
     http://localhost:8080/login

# 2. Fetch the CSRF token
curl -b jar.txt http://localhost:8080/api/v1/session

# 3. Book an appointment
curl -b jar.txt -X POST http://localhost:8080/api/v1/appointments \
     -H "Content-Type: application/json" \
     -H "X-CSRF-Token: <token from step 2>" \
     -d '{"patientName":"Kasun Fernando",
          "address":"14/3 Temple Road, Nugegoda",
          "contactNumber":"0771234567",
          "dentistId":1, "treatmentId":2,
          "date":"2026-10-01", "time":"09:00"}'

# 4. Read it back
curl -b jar.txt http://localhost:8080/api/v1/appointments/APT-2026-0001
